System shape

Postgres is authoritative. Edge memory is temporary.

Control reads current policy from Postgres for each Space-scoped request. Edge uses an immutable local snapshot for speed. The Edge snapshot never becomes the source of truth.

Control lane Every request
Caller Application Job, purge, or admin request
Runtime Control Async SpaceRegistry interface
Authority Postgres Current policy and credentials

No Control policy cache in the first version.

Media lane Most requests
Caller Browser Image, video, or PDF
Fast path One Edge isolate Local snapshot younger than 60s
On cold / expired Control → Postgres One atomic secret snapshot

Each isolate has its own snapshot and its own timer.

Edge cache lab

“Module scope” means one copy per isolate.

Cloudflare can run several isolates for the same Worker script. Requests that reach the same warm isolate reuse its variable. A different or new isolate starts cold and calls Control for its own snapshot.

Configuration ownership

Three kinds of configuration. Three clear homes.

This does not add a new runtime system. It only stops one kind of configuration from leaking into another kind.

Space-owned

What one application can do

Postgres + /admin

  • Public or private route class
  • Allowed source origins and resolvers
  • Quality policy
  • API tokens and capability keys
Deployment-owned

Where this Shutter instance runs

Railway + Cloudflare

  • Regions and custom domains
  • R2 and S3 bindings
  • Provider credentials
  • imgproxy process allowlist
Protocol-owned

What Shutter v1 means

Code + contracts

  • Versioned URL shapes
  • Capability purposes
  • Cache identity
  • Maximum lifetimes and fixed transforms

Implementation sequence

Finish configuration first. Add media delivery after.

Plans 01 through 03 are the current program. Plan 04 is later deployment cleanup. Plan 05 adds the CDN-style media front door.

01

Space registry schema

Now · one PR

Outcome: Postgres can store each Space policy and credential.

  • Use incrementing internal primary keys and unique business constraints.
  • Make the public Space identifier and route class immutable.
  • Decommission old Spaces. Do not delete or reuse their identifiers.
  • Seal capability keys with AES-256-GCM.
  • Add one async SpaceRegistry interface with Postgres and test adapters.
Read the implementation plan →
02

Registry cutover

Now · one PR

Outcome: Runtime code no longer reads tenant policy from the repository or JSON environment values.

  • Control reads Postgres on every Space-scoped request.
  • Edge pulls one atomic policy-and-key snapshot from Control.
  • Each Edge isolate caches that snapshot for no more than 60 seconds.
  • Executors receive only the origin rules in their claim.
  • Use one maintenance window of up to 10 minutes. Do not add dual reads.
  • Delete `packages/space-config` and replace real test identifiers.
Read the implementation plan →
03

Admin surface

Now · one PR

Outcome: A self-hoster creates and manages Spaces without code edits.

  • Keep `ADMIN_BOOTSTRAP_TOKEN` as a Railway `preserve()` value.
  • Create, edit, and decommission Spaces from `/admin`.
  • Do not show edit controls for the Space identifier or route class.
  • Issue API tokens and capability keys with one-time secret display.
  • Rotate capability keys with a manual application update and overlap window.
  • Show Edge refresh generation and imgproxy allowlist coverage.
  • Do not ask operators to paste policy or key JSON into Cloudflare.

05

Media delivery

After configuration

Outcome: All supported media can use one Shutter hostname.

  • Add Source Delivery for unchanged original bytes.
  • Support images, video range requests, and PDFs.
  • Keep Image Optimization as an optional sibling route.
  • Keep video posters and PDF covers as Master Previews.
  • Use Source ID for cache and purge identity, not the locator.
  • Do not copy authoritative originals into Shutter storage in v1.

Deferred operations

Production change

A simple cutover inside a 10-minute window.

The accepted downtime removes the need for dual-read code. Test the import against a production copy before this window starts.

  1. T+00 Pause traffic

    Start maintenance mode for Space routes.

  2. T+01 Import

    Write current policy, token hashes, and keys to Postgres.

  3. T+03 Compare

    Read the snapshot back and compare all old values.

  4. T+05 Deploy

    Release Control, Executors, and Edge.

  5. T+08 Prove

    Test old credentials plus public and private routes.

  6. T+10 Resume

    End maintenance mode and remove old environment values.

Plan 05 direction

One URL origin. Three media paths.

Shutter becomes the front door for supported media. It still leaves uploads, source ownership, and the media catalog with the consuming application.

Application-owned

Source storage

Immutable original images, videos, and PDFs.

Shutter Edge

One public media origin with Space policy and authorization.

Source Delivery

Original bytes, `GET`, `HEAD`, video ranges, and PDF viewing.

Image Optimization

Optional resize and WebP output for image sources.

Master Preview

Video posters and PDF covers, then optional image resizing.

Manual key rotation

Add the new key to Shutter first. Then update the consuming application to issue new capabilities with that key. Keep the old key in Shutter for 24 hours, and then disable it. The application owner coordinates both updates; Shutter needs no automatic handoff.
